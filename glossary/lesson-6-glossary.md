# Глоссарий к уроку 6: ООП, SOLID принципы и TypeScript

---

## А

### Абстракция {#абстракция}
**Что это:** Выделение существенных характеристик объекта и игнорирование несущественных деталей.

**Зачем нужна:** Позволяет работать с объектами на высоком уровне, не вдаваясь в детали реализации.

**Основные принципы:** Скрытие сложности, упрощение интерфейса, фокусировка на функциональности.

**В тестировании:** Создание Page Object Model, где детали взаимодействия с DOM скрыты за простыми методами.

---

## Б

### Балансировка шардов {#балансировка-шардов}
**Что это:** Равномерное распределение тестов между шардами для оптимального использования ресурсов.

**Зачем нужна:** Обеспечивает, что все шарды загружены равномерно, избегая "пустых" шардов.

**Основные принципы:** Автоматическое распределение по времени выполнения, учет зависимостей, оптимизация общего времени.

**Пример:**
```javascript
// Хорошая балансировка - тесты распределены равномерно
Шард 1: 25 тестов, ~5 минут
Шард 2: 24 теста, ~5 минут  
Шард 3: 26 тестов, ~5 минут
Шард 4: 25 тестов, ~5 минут
```

---

## В

### Валидация {#валидация}
**Что это:** Проверка корректности данных или состояния перед их использованием.

**Зачем нужна:** Предотвращает ошибки и обеспечивает корректность работы программы.

**Основные принципы:** Проверка на раннем этапе, четкие правила валидации, информативные сообщения об ошибках.

**В тестировании:** Проверка входных данных, валидация состояния страницы, проверка API ответов.

---

## Д

### Динамическая типизация {#динамическая-типизация}
**Что это:** Проверка типов данных во время выполнения программы.

**Зачем нужна:** Обеспечивает гибкость в изменении типов переменных и быструю разработку.

**Основные принципы:** Типы определяются в runtime, возможность изменения типов, гибкость.

**В тестировании:** JavaScript позволяет быстро создавать тесты без строгой типизации, но может приводить к ошибкам.

---

## З

### Зависимость {#зависимость}
**Что это:** Связь между модулями, где один модуль использует функциональность другого.

**Зачем нужна:** Позволяет создавать сложные системы, разделяя ответственность между компонентами.

**Основные принципы:** Минимизация зависимостей, слабая связанность, высокая когезия.

**В тестировании:** Тесты должны иметь минимальные зависимости друг от друга для независимого выполнения.

---

## И

### Инкапсуляция {#инкапсуляция}
**Что это:** Объединение данных и методов в единый объект с контролируемым доступом.

**Зачем нужна:** Скрывает внутреннюю реализацию и защищает данные от внешнего вмешательства.

**Основные принципы:** Скрытие деталей, контролируемый доступ, объединение связанных данных.

**В тестировании:** Page Object инкапсулирует логику работы с конкретной страницей.

---

## К

### Классы в JS {#классы-в-js}
**Что это:** Синтаксический сахар над прототипным наследованием, введенный в ES6.

**Зачем нужны:** Упрощают создание объектов с общим поведением и делают код более читаемым.

**Основные принципы:** Синтаксис похож на классические ООП языки, но под капотом - прототипы.

**В тестировании:** Создание базовых классов для тестов, наследование общих методов.

---

### Композиция {#композиция}
**Что это:** Создание сложных объектов путем объединения более простых.

**Зачем нужна:** Альтернатива наследованию, обеспечивает гибкость и слабую связанность.

**Основные принципы:** "Предпочитай композицию наследованию", включение объектов, делегирование.

**В тестировании:** Создание тестовых утилит путем композиции простых функций.

---

## М

### Matrix Strategy {#matrix-strategy}
**Что это:** Стратегия GitHub Actions для создания параллельных jobs с разными параметрами.

**Зачем нужна:** Позволяет автоматически создавать множество jobs для sharding без дублирования кода.

**Основные принципы:** Определение матрицы параметров, автоматическое создание jobs, параллельное выполнение.

**Пример:**
```yaml
strategy:
  matrix:
    shardIndex: [1, 2, 3, 4]
    shardTotal: [4]
```

---

## Н

### Наследование {#наследование}
**Что это:** Механизм, позволяющий объектам наследовать свойства и методы от других объектов.

**Зачем нужно:** Позволяет переиспользовать код и создавать иерархии объектов.

**Основные принципы:** Переиспользование кода, расширение функциональности, создание иерархий.

**В тестировании:** Базовые тестовые классы, наследование общих методов тестирования.

---

## О

### Объединение отчетов {#объединение-отчетов}
**Что это:** Процесс создания единого отчета из результатов всех шардов.

**Зачем нужен:** Позволяет получить полную картину выполнения всех тестов в удобном формате.

**Основные принципы:** Использование blob репортера, команда merge-reports, сохранение всех артефактов.

**Пример:**
```javascript
npx playwright merge-reports --reporter html ./all-blob-reports
```

---

### Объект {#объект}
**Что это:** Сущность, содержащая данные (свойства) и поведение (методы).

**Зачем нужен:** Позволяет моделировать реальные сущности и организовывать код.

**Основные принципы:** Инкапсуляция, наследование, полиморфизм, абстракция.

**В тестировании:** Page Objects, Test Data Objects, Configuration Objects.

---

## П

### Парадигмы программирования {#парадигмы-программирования}
**Что это:** Способы организации и структурирования кода для решения задач.

**Зачем нужны:** Определяют подход к решению проблем и стиль написания кода.

**Основные принципы:** Процедурное, функциональное, ООП, прототипное программирование.

**В тестировании:** Выбор подхода зависит от сложности тестов и команды.

---

### Полиморфизм {#полиморфизм}
**Что это:** Способность объектов с одинаковым интерфейсом иметь разное поведение.

**Зачем нужен:** Позволяет создавать гибкие и расширяемые системы.

**Основные принципы:** Единый интерфейс, разная реализация, переопределение методов.

**В тестировании:** Разные стратегии тестирования с одинаковым интерфейсом.

---

### Принцип единственной ответственности (SRP) {#принцип-единственной-ответственности}
**Что это:** Класс должен иметь только одну причину для изменения.

**Зачем нужен:** Упрощает тестирование, поддержку и понимание кода.

**Основные принципы:** Одна задача на класс, четкое разделение ответственности.

**В тестировании:** Каждый тест проверяет одну конкретную функциональность.

---

### Принцип инверсии зависимостей (DIP) {#принцип-инверсии-зависимостей}
**Что это:** Зависимости должны строиться на абстракциях, а не на конкретных классах.

**Зачем нужен:** Обеспечивает слабую связанность и упрощает тестирование.

**Основные принципы:** Зависимость от абстракций, инверсия контроля.

**В тестировании:** Использование моков и интерфейсов для тестирования.

---

### Принцип открытости/закрытости (OCP) {#принцип-открытости-закрытости}
**Что это:** Программные сущности должны быть открыты для расширения, но закрыты для модификации.

**Зачем нужен:** Позволяет добавлять новую функциональность без изменения существующего кода.

**Основные принципы:** Расширение через наследование/композицию, защита от изменений.

**В тестировании:** Добавление новых тестов без изменения базовой структуры.

---

### Принцип подстановки Лисков (LSP) {#принцип-подстановки-лисков}
**Что это:** Объекты базового класса могут быть заменены объектами его подклассов без изменения корректности программы.

**Зачем нужен:** Обеспечивает корректность наследования и упрощает тестирование.

**Основные принципы:** Сохранение контракта, корректная подстановка.

**В тестировании:** Базовые тесты должны работать с любыми наследниками.

---

### Принцип разделения интерфейса (ISP) {#принцип-разделения-интерфейса}
**Что это:** Клиенты не должны зависеть от методов, которые они не используют.

**Зачем нужен:** Избегает "толстых" интерфейсов и упрощает реализацию.

**Основные принципы:** Специализированные интерфейсы, минимальные зависимости.

**В тестировании:** Тесты зависят только от необходимых методов.

---

### Прототип {#прототип}
**Что это:** Объект, от которого наследуются свойства и методы.

**Зачем нужен:** Основа прототипного наследования в JavaScript.

**Основные принципы:** Цепочка прототипов, делегирование, Object.prototype.

**В тестировании:** Создание базовых объектов для тестов.

---

### Прототипное наследование {#прототипное-наследование}
**Что это:** Механизм наследования через прототипы объектов в JavaScript.

**Зачем нужно:** Позволяет создавать иерархии объектов без классических классов.

**Основные принципы:** Цепочка прототипов, делегирование, динамическое наследование.

**В тестировании:** Создание базовых тестовых объектов с общим поведением.

---

## С

### Сильная типизация {#сильная-типизация}
**Что это:** Строгие правила преобразования типов, требующие явного приведения.

**Зачем нужна:** Предотвращает неожиданные преобразования и делает код предсказуемым.

**Основные принципы:** Явное приведение типов, строгие правила, предсказуемость.

**В тестировании:** TypeScript помогает избежать ошибок типов в тестах.

---

### Система типов {#система-типов}
**Что это:** Набор правил для определения и проверки типов данных в программе.

**Зачем нужна:** Предотвращает ошибки, улучшает читаемость и упрощает рефакторинг.

**Основные принципы:** Классификация данных, проверка корректности, документация.

**В тестировании:** Типы помогают понять, какие данные ожидаются в тестах.

---

### Слабая типизация {#слабая-типизация}
**Что это:** Автоматическое приведение типов без явного указания.

**Зачем нужна:** Обеспечивает гибкость и быстроту разработки.

**Основные принципы:** Автоматические преобразования, гибкость, неявность.

**В тестировании:** JavaScript позволяет быстро писать тесты, но может скрывать ошибки.

---

### SOLID принципы {#solid-принципы}
**Что это:** Пять принципов объектно-ориентированного программирования для создания качественного кода.

**Зачем нужны:** Улучшают читаемость, тестируемость и поддерживаемость кода.

**Основные принципы:** SRP, OCP, LSP, ISP, DIP.

**В тестировании:** Помогают создавать тестируемый и поддерживаемый код.

---

### Статическая типизация {#статическая-типизация}
**Что это:** Проверка типов на этапе компиляции.

**Зачем нужна:** Раннее обнаружение ошибок и улучшение качества кода.

**Основные принципы:** Проверка до выполнения, лучшая поддержка IDE, строгость.

**В тестировании:** TypeScript помогает найти ошибки до запуска тестов.

---

## Т

### Типизация {#типизация}
**Что это:** Способ классификации данных и проверки их корректности.

**Зачем нужна:** Предотвращает ошибки и улучшает понимание кода.

**Основные принципы:** Классификация, проверка, документация.

**В тестировании:** Понимание типов данных критично для написания корректных тестов.

---

## У

### Уровни гранулярности {#уровни-гранулярности}
**Что это:** Способы разделения тестов при sharding - на уровне отдельных тестов или файлов.

**Зачем нужен:** Определяет, как именно тесты будут распределены между шардами для оптимальной производительности.

**Основные принципы:** Тестовый уровень (fullyParallel: true) vs файловый уровень.

**Пример:**
```javascript
export default defineConfig({
  fullyParallel: true,  // Тестовый уровень
});
```

---

## Ф

### Функциональное программирование {#функциональное-программирование}
**Что это:** Парадигма, основанная на использовании функций и избежании изменяемого состояния.

**Зачем нужно:** Обеспечивает предсказуемость, тестируемость и параллелизм.

**Основные принципы:** Чистые функции, иммутабельность, композиция функций.

**В тестировании:** Функциональный подход упрощает тестирование и отладку.

---

## Ш

### Sharding {#sharding}
**Что это:** Техника разделения тестов на параллельные части (шарды) для ускорения выполнения.

**Зачем нужен:** Позволяет выполнять тесты одновременно на разных машинах, значительно сокращая общее время выполнения.

**Основные принципы:** Разделение тестов на равные части, параллельное выполнение, независимость шардов.

**Пример:**
```javascript
npx playwright test --shard=1/4  // Первый шард
npx playwright test --shard=2/4  // Второй шард
```

---

## Э

### Event Loop {#event-loop}
**Что это:** Механизм JavaScript для обработки асинхронных операций.

**Зачем нужен:** Координирует выполнение синхронного и асинхронного кода.

**Основные принципы:** Call Stack, Web APIs, Callback Queue, Microtask Queue.

**В тестировании:** Понимание Event Loop критично для асинхронных тестов.

---

## Я

### Язык программирования {#язык-программирования}
**Что это:** Формальная система для написания компьютерных программ.

**Зачем нужен:** Позволяет создавать программы для решения различных задач.

**Основные принципы:** Синтаксис, семантика, парадигмы программирования.

**В тестировании:** Выбор языка влияет на возможности и сложность тестирования.
