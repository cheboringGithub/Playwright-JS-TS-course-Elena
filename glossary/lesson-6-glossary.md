# Глоссарий к уроку 6: Оптимизация тестов с помощью Sharding

---

## S

### Sharding {#sharding}
**Что это:** Техника разделения тестов на параллельные части (шарды) для ускорения выполнения.

**Зачем нужен:** Позволяет выполнять тесты одновременно на разных машинах, значительно сокращая общее время выполнения.

**Основные принципы:** Разделение тестов на равные части, параллельное выполнение, независимость шардов.

**Пример:**
```javascript
// Разделение на 4 шарда
npx playwright test --shard=1/4  // Первый шард
npx playwright test --shard=2/4  // Второй шард
npx playwright test --shard=3/4  // Третий шард
npx playwright test --shard=4/4  // Четвертый шард

// Каждый шард выполняется параллельно
// Общее время = время самого медленного шарда
```

## У

### Уровни гранулярности {#уровни-гранулярности}
**Что это:** Способы разделения тестов при sharding - на уровне отдельных тестов или файлов.

**Зачем нужен:** Определяет, как именно тесты будут распределены между шардами для оптимальной производительности.

**Основные принципы:** Тестовый уровень (fullyParallel: true) vs файловый уровень, влияние на балансировку.

**Пример:**
```javascript
// playwright.config.ts
export default defineConfig({
  fullyParallel: true,  // Тестовый уровень - каждый тест может быть в разных шардах
  // vs
  // fullyParallel: false - файловый уровень - весь файл в одном шарде
});
```

## Б

### Балансировка шардов {#балансировка-шардов}
**Что это:** Равномерное распределение тестов между шардами для оптимального использования ресурсов.

**Зачем нужна:** Обеспечивает, что все шарды загружены равномерно, избегая "пустых" шардов.

**Основные принципы:** Автоматическое распределение по времени выполнения, учет зависимостей, оптимизация общего времени.

**Пример:**
```javascript
// Хорошая балансировка - тесты распределены равномерно
Шард 1: 25 тестов, ~5 минут
Шард 2: 24 теста, ~5 минут  
Шард 3: 26 тестов, ~5 минут
Шард 4: 25 тестов, ~5 минут

// Плохая балансировка - неравномерное распределение
Шард 1: 80 тестов, ~15 минут
Шард 2: 5 тестов, ~1 минута
Шард 3: 10 тестов, ~2 минуты
Шард 4: 5 тестов, ~1 минута
```

## О

### Объединение отчетов {#объединение-отчетов}
**Что это:** Процесс создания единого отчета из результатов всех шардов.

**Зачем нужен:** Позволяет получить полную картину выполнения всех тестов в удобном формате.

**Основные принципы:** Использование blob репортера, команда merge-reports, сохранение всех артефактов.

**Пример:**
```javascript
// 1. Генерация blob отчетов в каждом шарде
reporter: process.env.CI ? 'blob' : 'html'

// 2. Загрузка blob отчетов в единую директорию
// 3. Объединение командой
npx playwright merge-reports --reporter html ./all-blob-reports

// Результат: единый HTML отчет со всеми тестами
```

## M

### Matrix Strategy {#matrix-strategy}
**Что это:** Стратегия GitHub Actions для создания параллельных jobs с разными параметрами.

**Зачем нужна:** Позволяет автоматически создавать множество jobs для sharding без дублирования кода.

**Основные принципы:** Определение матрицы параметров, автоматическое создание jobs, параллельное выполнение.

**Пример:**
```yaml
# GitHub Actions workflow
strategy:
  matrix:
    shardIndex: [1, 2, 3, 4]
    shardTotal: [4]
    
# Автоматически создаст 4 jobs:
# - shardIndex: 1, shardTotal: 4
# - shardIndex: 2, shardTotal: 4  
# - shardIndex: 3, shardTotal: 4
# - shardIndex: 4, shardTotal: 4
```

## B

### Blob Reporter {#blob-reporter}
**Что это:** Специальный репортер Playwright, который сохраняет полную информацию о тестах для последующего объединения.

**Зачем нужен:** Сохраняет все детали тестов (трейсы, скриншоты, ошибки) для создания единого отчета.

**Основные принципы:** Полное сохранение информации, совместимость с merge-reports, оптимизация для CI.

**Пример:**
```javascript
// playwright.config.ts
export default defineConfig({
  reporter: process.env.CI ? 'blob' : 'html',
  // В CI генерируется blob отчет
  // В локальной разработке - HTML отчет
});
```
