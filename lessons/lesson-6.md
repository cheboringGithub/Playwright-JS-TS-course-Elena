## Тема 1: Оптимизация тестов с помощью Sharding

**Ключевые вопросы:**

### 1. [**Sharding**]({{ site.baseurl }}/glossary/lesson-6-glossary#sharding){:data-glossary-term="Sharding" data-glossary-definition="Разделение тестов на параллельные части для ускорения выполнения"}
- **Что такое Sharding в Playwright?**
  - Разделение тестов на меньшие части (шарды)
  - Параллельное выполнение на разных машинах
  - Ускорение общего времени выполнения тестов

- **Как работает разделение тестов на части?**
  - Использование флага `--shard=x/y`
  - Каждый шард выполняет свою часть тестов
  - Независимое выполнение шардов

### 2. [**Уровни гранулярности**]({{ site.baseurl }}/glossary/lesson-6-glossary#уровни-гранулярности){:data-glossary-term="Уровни гранулярности" data-glossary-definition="Способы разделения тестов при sharding"}
- **Что означает `fullyParallel: true`?**
  - Тесты выполняются на уровне отдельных тестов
  - Лучшее распределение нагрузки между шардами
  - Оптимальное использование ресурсов

- **В чем разница между тестовым и файловым уровнем?**
  - Тестовый уровень: каждый тест может быть в разных шардах
  - Файловый уровень: весь файл тестов в одном шарде
  - Влияние на балансировку шардов

### 3. [**Балансировка шардов**]({{ site.baseurl }}/glossary/lesson-6-glossary#балансировка-шардов){:data-glossary-term="Балансировка шардов" data-glossary-definition="Равномерное распределение тестов между шардами"}
- **Как Playwright распределяет тесты между шардами?**
  - Автоматическое распределение по времени выполнения
  - Учет зависимостей между тестами
  - Оптимизация для минимального общего времени

- **Почему важно учитывать размер тестовых файлов?**
  - Неравномерное распределение нагрузки
  - Возможность "пустых" шардов
  - Рекомендации по организации тестов

### 4. [**Объединение отчетов**]({{ site.baseurl }}/glossary/lesson-6-glossary#объединение-отчетов){:data-glossary-term="Объединение отчетов" data-glossary-definition="Создание единого отчета из результатов всех шардов"}
- **Как работает `blob` репортер?**
  - Сохранение полной информации о тестах
  - Включение трейсов, скриншотов и других артефактов
  - Возможность объединения с другими отчетами

- **Как объединить отчеты от разных шардов?**
  - Команда `npx playwright merge-reports`
  - Загрузка blob отчетов в единую директорию
  - Создание HTML или других форматов отчетов

## Тема 2: ООП в JavaScript

**Ключевые вопросы:**

### 1. [**Парадигмы программирования**]({{ site.baseurl }}/glossary/lesson-6-glossary#парадигмы-программирования){:data-glossary-term="Парадигмы программирования" data-glossary-definition="Способы организации и структурирования кода"}
- **Какие парадигмы поддерживает JavaScript?**
  - Процедурное программирование
  - Функциональное программирование
  - Объектно-ориентированное программирование
  - Прототипное программирование

- **Почему JS называют мультипарадигменным языком?**
  - Гибкость в выборе подхода
  - Возможность комбинировать парадигмы
  - Адаптация под конкретную задачу

### 2. [**Основные принципы ООП**]({{ site.baseurl }}/glossary/lesson-6-glossary#принципы-ооп){:data-glossary-term="Принципы ООП" data-glossary-definition="Фундаментальные концепции объектно-ориентированного программирования"}
- **Что такое инкапсуляция в JS?**
  - Объединение данных и методов в объект
  - Скрытие внутренней реализации
  - Использование замыканий для приватности

- **Как работает наследование в JavaScript?**
  - Прототипная цепочка
  - Делегирование методов
  - Отсутствие классического наследования

- **Что такое полиморфизм в JS?**
  - Разные объекты могут иметь одинаковые методы
  - Переопределение методов в наследниках
  - Утиная типизация

### 3. [**Особенности ООП в JavaScript**]({{ site.baseurl }}/glossary/lesson-6-glossary#особенности-ооп-в-js){:data-glossary-term="Особенности ООП в JS" data-glossary-definition="Уникальные характеристики объектно-ориентированного подхода в JavaScript"}
- **Почему JS не является классическим ООП языком?**
  - Отсутствие классов (до ES6)
  - Прототипное наследование вместо классового
  - Динамическая типизация

- **Как работают объекты в JS?**
  - Объекты как ассоциативные массивы
  - Возможность добавления/удаления свойств
  - Ссылочная природа объектов

### 4. [**Прототипное наследование**]({{ site.baseurl }}/glossary/lesson-6-glossary#прототипное-наследование){:data-glossary-term="Прототипное наследование" data-glossary-definition="Механизм наследования через прототипы объектов"}
- **Что такое прототип?**
  - Ссылка на родительский объект
  - Цепочка прототипов для поиска свойств
  - `Object.prototype` как корень цепочки

- **Как работает `__proto__` и `prototype`?**
  - `__proto__` - ссылка на прототип экземпляра
  - `prototype` - свойство конструктора
  - Различия в использовании

### 5. [**Классы в JavaScript**]({{ site.baseurl }}/glossary/lesson-6-glossary#классы-в-js){:data-glossary-term="Классы в JS" data-glossary-definition="Синтаксический сахар над прототипным наследованием в ES6"}
- **Что на самом деле представляют классы в JS?**
  - Синтаксический сахар над прототипами
  - Функции-конструкторы в новом синтаксисе
  - Те же прототипы под капотом

- **Какие особенности у классов в JS?**
  - Отсутствие приватных полей (до ES2022)
  - Hoisting не работает как с функциями
  - Нельзя вызывать без `new`

## Тема 3: SOLID принципы в JavaScript

**Ключевые вопросы:**

### 1. [**Что такое SOLID**]({{ site.baseurl }}/glossary/lesson-6-glossary#solid-принципы){:data-glossary-term="SOLID принципы" data-glossary-definition="Пять принципов объектно-ориентированного программирования для создания качественного кода"}
- **Расшифровка аббревиатуры SOLID:**
  - **S** - Single Responsibility Principle (Принцип единственной ответственности)
  - **O** - Open/Closed Principle (Принцип открытости/закрытости)
  - **L** - Liskov Substitution Principle (Принцип подстановки Лисков)
  - **I** - Interface Segregation Principle (Принцип разделения интерфейса)
  - **D** - Dependency Inversion Principle (Принцип инверсии зависимостей)

- **Зачем нужны SOLID принципы?**
  - Улучшение читаемости кода
  - Упрощение тестирования
  - Облегчение рефакторинга
  - Снижение связанности компонентов

### 2. [**Принцип единственной ответственности (SRP)**]({{ site.baseurl }}/glossary/lesson-6-glossary#принцип-единственной-ответственности){:data-glossary-term="Принцип единственной ответственности" data-glossary-definition="Класс должен иметь только одну причину для изменения"}
- **Что означает "одна ответственность"?**
  - Класс/функция решает только одну задачу
  - Изменение одной функциональности не влияет на другую
  - Легче тестировать и поддерживать

- **Примеры нарушения SRP:**
  - Класс, который и валидирует данные, и сохраняет их, и отправляет уведомления
  - Функция, которая и парсит JSON, и обрабатывает бизнес-логику

### 3. [**Принцип открытости/закрытости (OCP)**]({{ site.baseurl }}/glossary/lesson-6-glossary#принцип-открытости-закрытости){:data-glossary-term="Принцип открытости/закрытости" data-glossary-definition="Программные сущности должны быть открыты для расширения, но закрыты для модификации"}
- **Как применять OCP в JavaScript?**
  - Использование наследования и композиции
  - Стратегии и паттерны проектирования
  - Конфигурация через параметры

- **Практические примеры:**
  - Плагинная архитектура
  - Middleware в Express.js
  - Обработчики событий

### 4. [**Принцип подстановки Лисков (LSP)**]({{ site.baseurl }}/glossary/lesson-6-glossary#принцип-подстановки-лисков){:data-glossary-term="Принцип подстановки Лисков" data-glossary-definition="Объекты базового класса могут быть заменены объектами его подклассов без изменения корректности программы"}
- **Что означает "корректная подстановка"?**
  - Наследник должен полностью реализовывать контракт родителя
  - Нельзя ужесточать предусловия
  - Нельзя ослаблять постусловия

- **Примеры в JavaScript:**
  - Переопределение методов без изменения сигнатуры
  - Сохранение ожидаемого поведения

### 5. [**Принцип разделения интерфейса (ISP)**]({{ site.baseurl }}/glossary/lesson-6-glossary#принцип-разделения-интерфейса){:data-glossary-term="Принцип разделения интерфейса" data-glossary-definition="Клиенты не должны зависеть от методов, которые они не используют"}
- **Как разделять интерфейсы?**
  - Создание специализированных интерфейсов
  - Избежание "толстых" интерфейсов
  - Использование композиции

### 6. [**Принцип инверсии зависимостей (DIP)**]({{ site.baseurl }}/glossary/lesson-6-glossary#принцип-инверсии-зависимостей){:data-glossary-term="Принцип инверсии зависимостей" data-glossary-definition="Зависимости должны строиться на абстракциях, а не на конкретных классах"}
- **Что означает "инверсия зависимостей"?**
  - Модули высокого уровня не зависят от модулей низкого уровня
  - Оба зависят от абстракций
  - Абстракции не зависят от деталей

- **Практическое применение:**
  - Dependency Injection
  - Использование интерфейсов
  - Тестирование через моки

## Тема 4: JavaScript vs TypeScript

**Ключевые вопросы:**

### 1. [**Система типов**]({{ site.baseurl }}/glossary/lesson-6-glossary#система-типов){:data-glossary-term="Система типов" data-glossary-definition="Набор правил для определения и проверки типов данных в программе"}
- **Что такое типизация в программировании?**
  - Способ классификации данных
  - Проверка корректности операций
  - Предотвращение ошибок на этапе компиляции

- **Как работает типизация в JavaScript?**
  - Динамическая типизация
  - Автоматическое приведение типов
  - Отсутствие проверки на этапе компиляции

### 2. [**Статическая vs Динамическая типизация**]({{ site.baseurl }}/glossary/lesson-6-glossary#статическая-типизация){:data-glossary-term="Статическая типизация" data-glossary-definition="Проверка типов на этапе компиляции"}
- **Статическая типизация (TypeScript):**
  - Проверка типов на этапе компиляции
  - Раннее обнаружение ошибок
  - Лучшая поддержка IDE
  - Более строгий контроль

- **Динамическая типизация (JavaScript):**
  - Проверка типов во время выполнения
  - Гибкость в изменении типов
  - Быстрое прототипирование
  - Возможность ошибок в runtime

### 3. [**Сильная vs Слабая типизация**]({{ site.baseurl }}/glossary/lesson-6-glossary#сильная-типизация){:data-glossary-term="Сильная типизация" data-glossary-definition="Строгие правила преобразования типов"}
- **Сильная типизация (TypeScript):**
  - Строгие правила преобразования типов
  - Явное приведение типов
  - Меньше неожиданного поведения
  - Более предсказуемый код

- **Слабая типизация (JavaScript):**
  - Автоматическое приведение типов
  - Неявные преобразования
  - Возможность неожиданных результатов
  - Требует внимания к деталям

### 4. [**Преимущества TypeScript**]({{ site.baseurl }}/glossary/lesson-6-glossary#преимущества-typescript){:data-glossary-term="Преимущества TypeScript" data-glossary-definition="Дополнительные возможности и улучшения по сравнению с JavaScript"}
- **Что дает TypeScript разработчику?**
  - Раннее обнаружение ошибок
  - Лучшая поддержка IDE (автодополнение, рефакторинг)
  - Документирование кода через типы
  - Упрощение рефакторинга

- **Практические преимущества:**
  - Меньше багов в production
  - Лучшая читаемость кода
  - Упрощение работы в команде
  - Поддержка современных возможностей JavaScript

### 5. [**Миграция с JavaScript на TypeScript**]({{ site.baseurl }}/glossary/lesson-6-glossary#миграция-на-typescript){:data-glossary-term="Миграция на TypeScript" data-glossary-definition="Постепенный переход от JavaScript к TypeScript"}
- **Как начать использовать TypeScript?**
  - Постепенное добавление типов
  - Использование `any` для сложных случаев
  - Настройка конфигурации
  - Интеграция с существующим проектом
